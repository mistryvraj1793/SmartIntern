Entity class:
	-->What is wrapper class? 
		->A wrapper class in Java is a class that wraps a primitive data type into an object.
			For example:
				int → Integer
				double → Double
				char → Character	
			int num = 10;  // Primitive type
			Integer obj = num;  // Wrapper class (Auto-boxing)
	-->Why Use Wrapper Classes Instead of Primitive Types? or why we use over the primitive type?
		->Allows Null Values → Wrapper classes can store null, but primitive types cannot.
			Integer num = null;  // Allowed
			int num2 = null;  // ❌ Error! Primitives cannot be null
		->Collections (List, Map, etc.) Need Objects → Java collections do not support primitive types, only objects.
			List<Integer> list = new ArrayList<>();  // ✅ Works with Wrapper class
			List<int> list2 = new ArrayList<>();  // ❌ Error! Primitive types not allowed
		->Useful for Type Conversions → Wrapper classes provide methods to convert data.
			String str = "123";
			int num = Integer.parseInt(str);  // Converts String to int
		->Supports Object-Oriented Features → Allows usage of methods for operations.
			Integer num = 10;
			System.out.println(num.toString());  // ✅ Converts to String

Password Encryption using Bcrypt:
	-->The Maven dependency provides cryptographic utilities from Spring Security		
	-->Why Use It?
		->Securely stores passwords instead of saving them as plain text.
		->Uses industry-standard encryption algorithms for security.
	
	-->Defining the Password Encoder in Application.java
		-->What does this do?
			->@Bean annotation makes this method a Spring-managed bean.
			->BCryptPasswordEncoder is created and returned as a Spring Bean.
			->This ensures that whenever Spring needs a PasswordEncoder, it will automatically use this instance.
			
		-->Injecting PasswordEncoder in SessionController:
		
		-->Encoding User Password in saveUser Method:
			-->Step-by-Step Process:
				->Get raw password from the entityUser object.
				->Encrypt the password using encoder.encode(...).
				->Print the hashed password (for debugging purposes).
				->Store the encoded password in entityUser.setPassword(...) before saving it to the database.
		--> Why is Password Encoding Important?
			->Security Best Practice: Never store raw passwords in the database.
			->BCrypt is Strong: It automatically handles salting and is resistant to brute-force attacks.
			->Different Hash Every Time: Even if two users have the same password, the stored hash will be different.
		-->Final summary:
			Step					Code													Purpose
			1. Define Encoder Bean	@Bean PasswordEncoder encoder() {...}					Creates a BCrypt encoder as a Spring bean.
			2. Inject Encoder		@Autowired PasswordEncoder encoder;						Allows SessionController to use the encoder.
			3. Encrypt Password		encoder.encode(entityUser.getPassword())				Hashes the password before storing it.
			4. Verify Password		encoder.matches(enteredPassword, storedHashedPassword)	Checks if the entered password is correct.	

		-->Difference Between Both BCryptPasswordEncoder
			Code							Explanation
			new BCryptPasswordEncoder();	Uses default strength (10 rounds), which is a good balance between security and speed.
			new BCryptPasswordEncoder(5);	Uses 5 rounds, making it faster but less secure.
				->Key Points to Note:
				Higher rounds = More security but slower processing.
				Lower rounds = Faster but easier to crack.
				Default (10 rounds) is recommended for a good balance.
				If security is critical, use 12+ rounds, but it will be slower.
