mysql:
	-->command:use smartintern; or USE smartintern;
		->Switches the active database to smartintern.
		->All subsequent queries (e.g., SHOW TABLES;, SELECT * FROM users;) will run within the smartintern database.
		->If the database does not exist, MySQL will return an error.
	
	-->command:show tables; or SHOW TABLES;
		->Displays a list of all tables in the currently selected database (smartintern).
		->If the database is empty, it will return:
			output:Empty set (0.00 sec)
		if tables exist:
			output:	+----------------+
					| Tables_in_smartintern |
					+----------------+
					| users          |
					| employees      |
					| projects       |
					+----------------+	
				
	-->Why is AUTO_INCREMENT Missing?
		->Table Already Created Without AUTO_INCREMENT
			If the table was created before you added @GeneratedValue(strategy = GenerationType.IDENTITY), MySQL did not update it.
		->Hibernate Did Not Modify the Column
			Even if you set @GeneratedValue(strategy = GenerationType.IDENTITY), Hibernate does not change existing tables automatically.
		->auto_increment do not see in the "Extra" column then 
		->Hibernate may not have created the column with AUTO_INCREMENT if:
		->The table already existed before running your Spring Boot app.
		->The table schema was not updated properly.
	
		-->command:ALTER TABLE users MODIFY COLUMN userId INT AUTO_INCREMENT;
			->DESC users;
					->The command DESC users; (short for DESCRIBE users;) 
				  is used in MySQL to display the structure/schema of the users table. 
				  It shows details about each column in the table, including its name, 
				  data type, key constraints, default values, and extra attributes.
			output: +--------+---------+------+-----+---------+----------------+
					| Field  | Type    | Null | Key | Default | Extra          |
					+--------+---------+------+-----+---------+----------------+
					| userId | int(11) | NO   | PRI | NULL    | auto_increment |
					+--------+---------+------+-----+---------+----------------+
			Field->	The name of the column (userId)
			Type->	Data type of the column (int(11))
			Null->	Whether the column allows NULL values (NO means it cannot be NULL)
			Key->	If the column is a Primary Key (PRI), Foreign Key (FOR), or Unique Key (UNI)
			Default->	The default value for this column (if any)
			Extra->	Any additional info (e.g., auto_increment means MySQL automatically increases the value for new rows)

Entity class:
	-->What is wrapper class? 
		->A wrapper class in Java is a class that wraps a primitive data type into an object.
			For example:
				int → Integer
				double → Double
				char → Character	
			int num = 10;  // Primitive type
			Integer obj = num;  // Wrapper class (Auto-boxing)
	-->Why Use Wrapper Classes Instead of Primitive Types? or why we use over the primitive type?
		->Allows Null Values → Wrapper classes can store null, but primitive types cannot.
			Integer num = null;  // Allowed
			int num2 = null;  // ❌ Error! Primitives cannot be null
		->Collections (List, Map, etc.) Need Objects → Java collections do not support primitive types, only objects.
			List<Integer> list = new ArrayList<>();  // ✅ Works with Wrapper class
			List<int> list2 = new ArrayList<>();  // ❌ Error! Primitive types not allowed
		->Useful for Type Conversions → Wrapper classes provide methods to convert data.
			String str = "123";
			int num = Integer.parseInt(str);  // Converts String to int
		->Supports Object-Oriented Features → Allows usage of methods for operations.
			Integer num = 10;
			System.out.println(num.toString());  // ✅ Converts to String
